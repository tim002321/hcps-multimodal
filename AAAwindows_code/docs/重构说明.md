# 目录整理与可读性改造说明

> 本次改造只动**结构与命名**，不动协议与算法。所有能被验证的行为都做了前后对比，
> 结果见第 4 节。想知道程序怎么跑，看 `docs/架构说明.md`。

---

## 1. 为什么要改

改造前 9 个 `.py` 全平铺在根目录，读代码时最常遇到的三个问题：

1. **分不清谁在用谁**。`shouhuan.py` 有 704 行，主流程只用到其中 `ProtocolParser`
   一个类，另外 380 行是早期独立调试用的 `BluetoothReceiver` / `SerialReceiver` /
   演示 main。看代码的人会以为这些也在跑。
2. **同名逻辑两份**。`dump_services()` 在心电和手环两个模块里各写了一遍；
   `config.ini` 的解析在 `main.py` / `run_monitor.py` / `tools/ble_scan.py` 写了三遍，
   而且键名和默认值已经开始走偏（`main.py` 压根没读 `scan_attempts`）。
3. **配置项靠猜**。`cfg['bracelet']['notify_uuid']` 这种嵌套字典，不看实现不知道有哪些键。

## 3. 具体改了什么

### 3.1 拆分 `shouhuan.py`

| 内容 | 去向 |
|---|---|
| 协议常量、4 个数据类、`ProtocolParser` | `devices/bracelet_protocol.py` |
| `COMMON_NOTIFY_UUIDS` | `devices/bracelet_protocol.py`（接收端从这里 import） |
| `BluetoothReceiver`、`SerialReceiver`、`demo_*`、`__main__` | `devices/legacy_bracelet.py` |

拆完之后协议文件只有 330 行、零蓝牙依赖，可以离线单测；
调试脚本仍能 `python devices/legacy_bracelet.py --demo` 用协议文档的示例帧自检。

顺手做的事：
- 把 `feed()` 里 20 行的「类型 → 载荷偏移/包长」if-elif 链收成一个 `_layout()` 纯函数；
- 把 `_parse_ppg_accel` 里 `hi/lo/val` 的临时变量命名改成有含义的 `b0/b1/b2`、`value`；
- 未使用的 `status` 变量（PPG 每通道的状态字节）注释说明「已知不用」，避免下次有人以为漏解析。

### 3.2 提取 `devices/ble_utils.py`

原来两处重复的实现合并成一份：

```python
iter_characteristics(client)          # 屏蔽 bleak 的 services → characteristics 两层嵌套
dump_services(client, tag='ecg')      # 原来心电/手环各一份，仅前缀不同
find_characteristics(client, ('notify',))
scan_for_names(names, timeout)        # 原来两处 scan 循环里各写一遍的匹配逻辑
```

`scan_for_names` 收了口之后，两个模块的「扫描 → 匹配 → 起连接任务」循环都短了 10 行左右。

### 3.3 新增 `core/config.py`

```python
cfg = Config.load()          # 一次读完，字段即含义
cfg.ecg_names                # ['E1220511000413', ...]
cfg.bracelet_scan_attempts   # 10
cfg.out_file                 # None 或 'ecg_data.jsonl'
```

- 所有默认值与 `config.ini` 里的注释一致，缺项不报错；
- `at_least_one_device()` 把「一个设备都没配」的判断集中到一处；
- `describe()` 给出一行启动摘要，跑起来先确认读到的确实是这份配置。

**顺带修掉一个真实缺陷**：改造前 `main.py` 不读 `scan_attempts`，
所以「连续扫 10 次才报未找到」这条策略在纯采集模式下从来没生效过（一直用代码里的默认 10，
看起来一样，但配置改成 5 就不管用了）。现在两个入口都走同一个字段。

### 3.4 数据目录改为绝对路径

`core/db_storage.py` 原来写死 `DATA_DIR = "data"`，是相对**当前工作目录**的。
从仓库根目录启动采集，数据库会建到 `PyCharmMiscProject/data/` 而不是
`AAAwindows_code/data/`。现在由 `core/config.py` 按文件位置推导：

```python
PROJECT_ROOT = <AAAwindows_code>
DATA_DIR     = <AAAwindows_code>/data
```

### 3.5 修掉一个只要点「回放」就崩的旧 bug

`ui/replay.py` 的 `ReplayPlayer` 用 `self._stop = threading.Event()`。
`threading.Thread` 内部有个 `_stop()` **方法**，属性把它盖掉了，于是
`player.is_alive()` 一调用就抛：

```
TypeError: 'Event' object is not callable
```

即：改造前在「状态」页点开始回放 → 界面 on_tick 里查 `is_alive()` → 直接抛异常。
`camera_receiver.py` 里明明有注释写着「注意别叫 `_stop`：Thread 自带 `_stop()` 方法」，
`ReplayPlayer` 漏了。已改名为 `_stop_event` 并加了注释。

### 3.6 文档与命令路径

- 新增 `docs/架构说明.md`（逻辑说明）、本篇（改造说明）；
- `README.md` 的目录结构与命令路径按新结构更新；
- `DEVELOPMENT_GUIDE.md` 的「文件结构」「模块详解」章节同步。

> 如果你本地有旧脚本/快捷方式在调 `python ble_ecg_receiver.py` 或
> `python tools\ble_scan.py`，需要改成 `python main.py` / `python tools/ble/ble_scan.py`。

## 5. 其他顺手清理

- 删除无用的 `__pycache__/`（改造前根目录和 tools 下都有 3.12 的旧字节码）；
- `tools/*` 里计算项目根目录的 `ROOT` 从写死两层 `dirname` 改为与新的层级匹配，
  并统一了 `sys.path` 注入方式；
- `devices/__init__.py`、`core/__init__.py` 写了分层说明 + `__all__`，
  `import core` / `import devices` 就能看到这层对外提供什么。

## 6. 没做的事（留给后续）

1. **两个接收模块的连接循环仍有重复**。`ecg_receiver.run_device` 与
   `bracelet_receiver.BraceletReceiver.run_device` 的状态机几乎一样
   （连接 → 订阅 → 保持 → finally 断开 → 重连）。合并需要一个设备无关的基类，
   属于行为级改动，本次没动。
2. **`data/` 里的历史库没有归档**。155 个文件中既有会话库也有旧的 `camera_*.db`，
   建议按月份归档或加 `.gitignore`（当前 `data/*.db` 是被 git 跟踪的，单个最大 18MB）。
3. **`config.ini` 里的设备名太长**（14 个心电设备）。如果现场只用 1~2 台，
   建议精简；多个设备名是为批量采集留的。
4. **没有单元测试**。协议解析已经可以离线测（`bracelet_protocol` 无蓝牙依赖），
   值得补一个 `pytest` 用例把本次的 6 组等价性场景固化下来。
