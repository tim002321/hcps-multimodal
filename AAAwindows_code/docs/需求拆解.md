### 3. 横轴改成「正着加」

`ui/widgets.py::ChartPanel.set_series(..., end_time=None)`：

- 传入 `end_time`（会话绝对秒数）时，`x = end_time - (n-1-序号)/rate`，横轴从 0 起一直增长；
- 不再有 `-6 … 0` 的负计数，黄色游标也跟着数据末端走（以前固定在 0，是因为末点恒为 0）；
- 各页面用计数器换算绝对时间（`ui/window.py::channel_end_time`）：
  心电/呼吸按采样点、三轴与体温按包数、PPG 按采样点、GSR 按样本。

实测：回放 291 秒的会话时，心电窗口横轴为 `4.178 → 7.106`（秒），单调递增、无负数。

### 4. 登录 / 被试信息录入

`ui/profile.py`：程序启动先弹「实验信息录入」，字段为 **人物名 / 组别 / 实验时间 / 总线 IP**。

- 目录规则：`data/<组别>/<人物名>_<YYYYmmdd_HHMMSS>/<时间戳>.db`
  例：`data/A组/张三_20261024_163000/20261024_163000.db`
- 姓名与组别做了文件名清洗（去掉 `\ / : * ? " < > |`），空值回落为「临时 / 未分组」；
- 点了「跳过（临时会话）」就不建子目录，直接落 `data/` 下（老行为）；
- 总线 IP 只在本次会话生效，**不回写 config.ini**（`configparser.write` 会把文件里的中文注释全丢掉）；
  要长期固定请直接改 `config.ini` 的 `[server] host`，对话框每次用那里的值预填。
- 自动化/截图自检可加 `--no-profile` 跳过对话框。

### 5. 数据分析：时间段勾选 + 特征提取

`ui/pages_extra.py::AnalysisPage` + `analysis/features.py`：

- 选会话 → 载入 → 自动填入起止时间（可编辑）→「只用选中区间」勾选 → 特征提取；
- 心电：HRV —— bpm / SDNN / RMSSD / pNN50 / SD1 / SD2 / VLF / LF / HF / LF-HF；
- 手环：PPG 交流耦合 → 带通 → 峰值检测 → 脉率 / 脉间期均值与标准差 / 脉搏幅度；
- 眼动、表情两栏固定输出 `n/a` 并写明「模型未接入」；
- 结果可导出 CSV（UTF-8-SIG，Excel 直接打开不乱码）。

**算不出来就给 n/a，不给假数**，四道门限：

| 门限 | 触发条件 | 输出 |
|---|---|---|
| 数据长度 | 有效点 < 5 秒 | `数据太短` |
| 信号质量 | 幅度范围过小 / 饱和占比过高 | `信号过弱` / `电极可能脱落` |
| 心率合理区间 | 中位 RR 换算后不在 30~220 bpm | `判定为噪声` |
| **R 峰覆盖率** | 采纳的 RR 总时长 / 整段时长 < 50% | `信号不连续` |

最后一条是这次新加的：实测库里有条 291 秒的记录，只在零星片段检出 R 峰，
中位数算出 178 bpm —— 算法"成功"了但结果是假的。加覆盖率门限后正确拒报（覆盖率 25%）。

## 二、部分完成 / 需要算法输入的

### 8. PPG 提脉搏 —— 基础版已完成

`analysis/features.py::extract_pulse`：去直流 → 差分移动平均带通 → 自适应阈值峰值 → 脉率/脉间期。

- 合成信号验证：1.2 Hz 脉搏 → 报 72.1 bpm（误差 0.1）；
- 真实库（`20261007_145730.db`）290 秒 → 402 个脉搏波、101.0 bpm；
- 无接触（信号平坦）→ `PPG 无脉搏信号（未贴合）`。

**没做的**：PPG 的 SpO₂（需要红光/红外双波长比值标定）、呼吸率（从 PPG 基线漂移提取）、
以及四通道融合（现在只用 PPG1，其余三通道未参与）。

### 9. 体温 —— 已经能出

体温来自心电包的 `11:13` 字节（int16 / 100），界面「心电」页的体温块与趋势曲线都在用。
之前看到 `32.04 ℃` 是**设备上报值本身异常**（电极/体温传感器未贴合），不是解析错误 ——
解析公式与主工程 `data_ecg.py` 一致。

## 三、🔴 需要你拍板的（现在做不了，缺输入）

### 🔴 A. 四导联处理方法

"四导联"至少有三种可能，处理方式完全不同：

| 可能 | 需要的处理 |
|---|---|
| 设备输出 I / II / III + aVR 等**四路同步波形** | 每路独立 R 峰检测 → 选主导联 → 计算电轴/ST 段 |
| 单路 ECG 的**四种滤波/增强结果** | 只要滤波链，不涉及多路同步 |
| 四路来自**不同设备**（时间不同步） | 需要先做时钟对齐（现在靠包号 + 到达时刻） |

**需要你提供**：① 具体哪四路；② 是同一 BLE 包里一次给齐还是要分包读；③ 采样率是否都是 250Hz；
④ 有没有现场数据的原始字节样例（一段 hex 就行）。

### 🔴 B. 四个模型具体是哪四个

我按常识先放了「负荷等级 / 情绪状态 / 疲劳程度 / 注意水平」，但不确定对不对。需要：
**模型名称 + 输入特征 + 输出类别 + 模型文件（.pkl / .cbm / .onnx）**。
主工程 `saved_models/` 里有 svm / catboost / xgboost 三个负荷模型，
如果这四个里包含它们，可以直接复用 `feature_names.txt` 的 10 维顺序。

### 🔴 C. 摄像头面捕（瞳孔直径 + 眨眼频率）

需要人脸/眼部关键点模型。可选路线：

1. **MediaPipe FaceMesh**（`pip install mediapipe`，含虹膜关键点 468~477，可算瞳孔直径与睁眼度）——
   不需要训练，最快落地，但瞳孔直径是"像素比"而非毫米，需要一次标定；
2. **自己训 YOLO 检测眼睛框** + 分类睁/闭 —— 与表情共用一套 YOLO 框架，但要标注数据；
3. 用现成虹膜分割模型（如 RITnet）—— 精度最高，依赖也最重。

识别不到眼睛时输出 `n/a`（这句需求已确认，会照做：返回 `None` + 原因，界面显示 n/a）。
**需要你选路线**，并确认：瞳孔直径要像素值还是要毫米（后者要标定卡/已知尺寸）。

### 🔴 D. YOLO 表情 + "或的逻辑"

"做成或的逻辑"我理解成两种，差别很大：

- **解释 1（多帧投票）**：连续 N 帧里任一阵营命中即判该表情 —— 属于时序后处理；
- **解释 2（多源触发）**：表情、眼动、HRV 任一判定异常就触发「状态异常」—— 属于决策融合。

**需要你确认是哪种**（或都不是）。另外需要 YOLO 权重与类别表（现在 `saved_models/` 里没有表情模型；
主工程 `face_model/` 下是 CNN3 + BlazeFace 的老方案，不是 YOLO）。

### 🔴 E. 手表离线数据传输

缺协议。需要：**手表端怎么存、怎么发起传输（BLE GATT 特征？USB？）、数据格式、断点续传要不要**。
如果是同一块绿光手环，可能是协议文档 `docs/绿光手环数据协议.docx` 里没展开的一个命令字 ——
把相关章节或抓到的报文给我就能接。

### 🔴 F. 总线上传协议

现在是"留了一个地址"（`config.ini [server] host/port`，登录界面可临时改）。
真正上传还缺：**传输层（TCP/UDP/MQTT）、帧格式、鉴权、失败重试策略、上传频率**。
如果参照主工程，它有 `[data_alert_win] broker/topic/port=1883`（MQTT）的痕迹，可沿用 MQTT。
