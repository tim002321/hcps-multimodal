HCPS 采集程序 · 使用说明
==================================

一、启动
  双击 HCPS.exe。
  第一次启动会稍微慢一点（要加载 torch 的 dll），之后正常。

二、换电脑 / 换目录
  直接把整个 HCPS 文件夹复制过去就行，不需要装 Python、不需要装依赖。
  所有路径都跟着 exe 走：
    HCPS.exe          主程序
    _internal\        运行时环境和资源（别删、别拆开）
    config.ini        设备名、阈值等配置（第一次运行自动生成，可改）
    data\             采集到的会话库（按 组别\姓名_时间 归档）
  放在中文目录、U 盘、别的盘符下都能跑，路径里不要有 & % 之类特殊字符。

三、先自检，再上现场
  打开命令行，在本目录执行：

      HCPS.exe --selftest

  结果会打印出来，同时写一份 selftest.log 到本目录。全 [ OK ] 才算就绪，
  有 [FAIL] 看对应行后面的原因。

  自检覆盖：配置文件 / 数据目录可写 / Qt 界面 / 模型文件 / 视觉配置 /
  onnxruntime / 人脸检测 / 哈欠模型 / 四通道融合管线 / 蓝牙后端 /
  串口与 LSL / 摄像头。

  其中「视觉配置」和「人脸检测后端」会明确写出当前跑在 CPU 还是 GPU：
      CPU（onnxruntime）  = 纯 CPU，现场够用（约 17fps 推理）
      GPU CUDA            = 已用上显卡
  换到装了 CUDA 的机器，把 config.ini 的 [vision] device 改成 cuda 即可。

四、现场要核对的两件事
  1. config.ini 的 [bluetooth] device_names：跟当天用的心电贴广播名对齐；
     手环 [bracelet] bracelet_names 同理。
  2. [vision] threshold 只是中性初值，首次使用请用
     tools\vision\calibrate_threshold.py 在本地素材上标定后再改。

五、常见问题
  * 杀毒软件报警：PyInstaller 打的包常被误判，加白名单即可。
  * 提示缺 Qt 平台插件：确认 _internal 目录是完整的，别只拷 exe。
  * 摄像头打不开：先关掉别的占用摄像头的程序（腾讯会议等）。

六、本次录进去的数据
  每一场会话库（data\组别\姓名_时间\时间戳.db）里除了心电、手环，还有两张视觉表：

    vision_frames   每秒一行：有没有脸、张口概率、状态、疲劳档位
    yawn_events     每判定一次哈欠一行：概率、持续秒数

  所以采集结束后，"这一场打了几个哈欠、什么时候开始发困"是可以事后查的，
  不用再靠回看录像数。注意：只有勾着「启用打哈欠检测」采集的场次才有这两张表。

  摄像头画面**不再存进数据库**（以前一帧一个 BLOB，一场 100 分钟能到 3~8 GB）。
  现在图片和录像都在同一场会话的目录下：

    data\组别\姓名_时间\camera_<时间戳>\frames\0000\000001.jpg …   逐帧图片
    data\组别\姓名_时间\camera_<时间戳>\video_<时间戳>.mp4           整段录像

  每 1000 帧一个子目录，避免一个文件夹里堆十几万个文件。库里只剩索引
  （时间、帧号、相对路径），一场会话的库从几个 GB 降到几十 MB，
  拷贝、翻页、备份都快；回放时按索引去文件夹取帧，画面和以前一样。
  库里仍保留 camera_frames / camera_sessions 两张表，老库（帧在 BLOB 里）
  也能照常回放，两套格式并存。

  config.ini 的 [camera] 里有两个开关：
    save_frames=true    关掉就只录像，不存逐帧图片
    save_video=true     关掉就只存图片，不录像

七、帧率
  默认 15fps（config.ini 的 [camera] fps）。哈欠检测本身只有 6~7Hz，15fps 足够，
  而且图片和录像的占用比 30fps 小一半。要更流畅的录像再改回 30，代价是占用翻倍。

八、哈欠检测看不清嘴时会怎么说
  摄像头装在头顶朝下，被试一低头看仪表，画面里就只剩头发和眼镜。旧版这时候
  仍会给出很高的"张嘴概率"，导致哈欠数字虚高。现在改成：

    · 看得见嘴  → 磁贴显示「正常/张嘴中/打哈欠」+ 张口概率
    · 看不见嘴  → 磁贴显示「低头·嘴不可见」（橙色），画面上人脸框标 HIDDEN
                  这一帧不判哈欠，也不计入张口概率

  下方提示行会写原因：low_conf（关键点看不清）、head_down（低头过度）、
  out_of_frame（嘴出画了）、too_small（人太远）。

  采集结束后，分析页「视觉」块里会多两行：
    嘴可见率(%)  —— 低于 85% 说明机位或距离不合适，该调摄像头
    低头占比(%)  —— 被试低头的时间比例

  三个可调参数在 config.ini 的 [vision] 里（详见 嘴部门控说明.md）：
    kp_conf=0.5           人坐得远、一直报低置信 → 降到 0.35
    mouth_low_ratio=0.95  报低头太频繁 → 调到 1.0（等于不判这条）
    gate_enabled=true     想对照旧行为 → 改 false

  提醒：改成这个口径后，哈欠次数会比以前少，这是把误报去掉的正常结果。

九、采样率与时间轴（离线分析脚本）
  会话库里一个蓝牙包的所有采样点共用一个时间戳（手环 PPG 每包约 14 点、心电每包
  80 点、加速度每包 1 点、皮电每包 10 点），所以"行数 ÷ 墙钟跨度"不能当采样率：
  中途断连过的库会算出 50 Hz 这种离谱值，滤波带、心率、频谱全跟着错。

  现在统一按额定采样率（PPG 250 / 心电 250 / 加速度 25 / 皮电 10 Hz），
  再用每秒锚点把墙钟漂移修回去，丢包和断连单独记成"断点"。

  想核对某个库：在命令行执行

      python 校对时间轴.py            校对 信号库 下全部库
      python 校对时间轴.py 某个.db    只校对这一个库
      python 校对时间轴.py --trials   校对 实验分段 下的分段库

  重点看两列：
    漂移(s)     墙钟比样本多出来多少。正数=少收了样本，负数=设备时钟略快
    残差p95     重建后的时间轴与设备到达时刻的偏差。手环一般 20~45 ms；
                心电 150~260 ms，这是每包 80 个点 + 主机计时精度 75 ms 的
                协议上限，再优化也降不下来

  注意：exe 里自带一份 ppg_pipeline 副本，改了源码要重新打包才对 exe 生效；
  想临时用源码版，启动前设环境变量 HCP_PPG_PIPELINE 指向 试飞院二期\ppg_pipeline。

十、老数据怎么把图片搬出来
  2026-11 之前的场次，摄像头帧还在会话库的 BLOB 里。想搬出来的话：

      python 抽帧到文件夹.py                 先干跑：只统计有多少帧、多少 MB
      python 抽帧到文件夹.py --apply          真的搬（图片落文件夹，库里改成路径）
      python 抽帧到文件夹.py --apply --vacuum 再压缩库文件，把腾出的空间还给磁盘

  实测现有 10 个库合计 51.8 GB 图片、约 110 万帧，`--apply` 全程约 40 分钟，
  `--vacuum` 再加十几分钟。搬之前请确认采集程序没在跑，并且磁盘留足空间
  （先写图片，再点压缩，中间最多占双份）。脚本每 500 行提交一次，中途断了
  再跑一遍会接着做（已搬过的行 jpeg 为空，自动跳过），不会重复写图。
  每个会话会生成一份 camera_<时间戳>_帧清单.csv，记着 行号/帧号/文件/字节数。

十一、心电波形为什么看起来干净了
  以前曲线画的是原始 ADC：一两个顶到 ±32000 的脱落点就能把整屏压成一条直线，
  直流偏移/基线漂移（±3000）比 QRS 本身（±300）大一个量级，看着全是"杂波"。

  现在显示前做两件事（**入库的仍是原始值，分析口径不变**）：

    · 先按 0.5 秒分块取中位数、再跨块取中位数，得到一个"抗伪迹的慢基线"；
      偏离它超过 1000（QRS 相对慢基线只有三四百）或顶到 ±23500 的点算伪迹。
      伪迹段短的（<0.3 秒）按前后补平，长的留空让曲线断开 —— 不拿直线假装
      还有信号
    · 再用 1 秒滑动均值去掉慢漂，NaN 段按"忽略缺失"计算，不会把后一秒带偏

  特意没有做低通或 50Hz 陷波：实测 9 个库 40~60Hz 能量只占 0.2%，而 QRS 半高宽
  只有 20 ms —— 一个 5 点滑动平均（正好是 250Hz 下 50Hz 的零点）会把双相 QRS
  正负抵消掉九成，波形直接消失。要加滤波请先看自己的数据再决定。

  曲线右上角那个 ADC 数值仍然是原始值，可以当作电极接触好坏的参考。
  效果对比见 图集\心电显示_清理前后.png。
